# 需求：多國語言（i18n）

## 目標

讓非中文使用者也能用：介面依系統語言自動顯示繁體中文或英文，並可手動指定。

## 使用者決定（2026-11-15）

- 語言：繁體中文（`zh-TW`）＋英文（`en`）。
- 自動偵測：系統語言是 zh-TW、zh-HK、zh-MO 或 zh-Hant 時用繁中，其他（含 zh-CN）一律英文。
- 設定頁可手動指定。

## 驗收條件

- AC-1：設定「一般」頁有「語言」選項：自動（依系統）／繁體中文／English，預設「自動」。
- AC-2：「自動」時，系統首選語言為 zh-TW／zh-HK／zh-MO／zh-Hant* 顯示繁中，其他顯示英文。
- AC-3：切換語言後不需重開程式，畫面所有文字（導覽、頁面、對話框、按鈕、提示、空狀態、相對時間）立即改為新語言。
- AC-4：系統匣選單與提示文字、視窗標題、系統通知使用目前語言（切換後下一次顯示即生效）。
- AC-5：新產生的事件紀錄與錯誤訊息使用目前語言；已產生的事件紀錄維持原文。
- AC-6：外部 claude 的 statusline「未儲存」字樣與 runner 視窗訊息依設定語言顯示。
- AC-7：繼續提示（`continue_prompt`）未設定時，預設值依語言（「繼續」／`continue`）；使用者自訂的值不變。
- AC-8：英文與繁中字典的鍵完全一致、每個字串的參數（`{name}`）一致，有自動測試檢查。
- AC-9：既有測試全部通過；typecheck 通過。

## 不做

- Python 版（`switcher/`）。
- 簡體中文與其他語言。
- `switcher-run` 的輸出（給 Claude 讀的機器訊息）維持原樣。
- 程式註解（維持繁中）。
- 和伺服器回傳文字比對的字串常數。
- 開發用 `mock-api.ts` 的假資料內容（只要能編譯）。

## 限制

- 不新增相依套件（字典＋自寫 `t()` 即可）。
- `src/core` 不得 import electron；字典模組必須是純 TS。
