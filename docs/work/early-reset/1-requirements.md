# 需求：額度提前恢復（重置卡）時自動解除用完標記

使用者（2026-11-15）：「如果我中途使用重置卡標記不會去掉 也不會自動切換」。

原因：帳號用完時寫入 `exhausted_until`（估計的重置時間）。之後所有判斷（`slotBlocked`、`pickNext`、`pickEarliest`、總覽警示）只看這個時間，額度提前恢復也不會解除。

## 驗收條件

- AC-1：用量 API 取得某帳號的新資料，且同時符合下列條件時，自動清除該帳號的 `exhausted_until`：
  - 資料時間晚於標記時間至少 60 秒；
  - 5 小時與 7 天視窗都低於切換門檻（沒有資料的視窗不算超過）。
  - 清除時記錄事件「{name} 的額度已恢復，清除用完標記」。
- AC-2：標記時記下標記時間（`exhausted_at`）。舊資料沒有 `exhausted_at` 時，以 `exhausted_until - 5 小時` 當作標記時間。
- AC-3：清除後立即生效：
  - 若正在等待重置（有 `resumeAt`），且恢復的是目前帳號 → 下一個 tick 送「繼續」（不等原本的時間）。
  - 恢復的是其他帳號 → 自動切換過去（live 模式，與一般自動切換相同流程），並對因額度停下的 session 送「繼續」（不受 900 秒限制，只限 `rate_limit`）。
  - 沒有在等待時 → 只清標記；之後的自動切換可選它。
- AC-4：使用中帳號同樣適用：使用中帳號標記用完、但 API 顯示已恢復 → 清除標記並移除總覽「全部用完」警示。
- AC-5：既有手動「清除用完標記」按鈕不變。
- AC-6：中英文；既有測試通過；新增測試涵蓋 AC-1～AC-4。

## 不做

- 直接偵測「重置卡」本身（沒有 API）；一律以用量資料判斷。

## 實作紀錄

- Claude Sonnet 實作（`prompt-T-1.md`），568 個測試通過。補充：切換後立即結束本輪 tick（避免以舊帳號資料觸發切回）；目前帳號恢復時同一 tick 送繼續；兩個視窗都沒資料不判定恢復。
- 主導者修正：原實作在沒有 `resumeAt`（App 重啟、或未啟用換到最早重置）時只清標記、不切換也不送繼續，正是使用者回報的情境 → live 模式下：
  - 目前帳號恢復 → 一律安排送繼續；
  - 其他帳號恢復且目前帳號仍被擋 → 切過去並送繼續。
  - restart 模式只清標記。
  - 補 3 個測試（共 14 個）。
- 使用者實測（v1.1.1）：舊版寫的標記沒有 `exhausted_at`，`exhausted_until` 為 7 天視窗重置（數天後），以 `until - 5h` 推算的標記時間在未來 → 永遠不清除。修正：沒有 `exhausted_at` 的舊標記，有低於門檻的用量資料即視為恢復（v1.1.2）。
