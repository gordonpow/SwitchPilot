# 需求：全部用完時換到最早重置的帳號

使用者（2026-11-15）：「如果兩個額度都滿了 就換到最早重置的那個帳號」。

## 驗收條件

- AC-1：自動切換找不到可用帳號（全部用完或被門檻擋下）時，改選「最早可用」的帳號：
  - 每個帳號的可用時間 = `exhausted_until` 與用量 API 中超過門檻的視窗 `resets_at` 兩者較晚者。
  - 跳過需要重新登入或 token 已失效的帳號。
- AC-2：最早可用的帳號不是目前帳號 → 切換過去（只換憑證，不重啟 claude）：
  - 記錄事件「所有帳號都用完，已換到最早重置的 {name}（{time} 重置）」；
  - 通知一次。
- AC-3：最早可用的就是目前帳號 → 不切換（維持現狀），一樣安排 AC-4。
- AC-4：live 模式下，到該帳號的可用時間＋60 秒時，對因額度停下的 claude 送「繼續」提示，規則與一般切換後相同（每個 session 一次）。
- AC-5：不得反覆切換：
  - 切換後到可用時間之前，再收到限流事件不再觸發切換；
  - 手動切換或清除用完標記時，取消已安排的「繼續」。
- AC-6：設定「帳號切換」頁有開關「全部用完時換到最早重置的帳號」，預設開啟；關閉時維持原本行為（不切換、只通知）。
- AC-7：中英文；既有測試通過；新增測試涵蓋 AC-1～AC-6。

## 不做

- restart 模式下為此重啟 claude（restart 模式只換憑證，不重啟、不送提示）。
